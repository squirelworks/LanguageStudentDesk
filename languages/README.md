# Languages Data Layer

Shared language data for LanguageStudentDesk tools.

## Structure

Each language has its own folder:

```
languages/
  japanese/
    meta.json
    characters.json   (optional, for future)
  klingon/
    meta.json
  arabic/
    meta.json
  ...
```

## meta.json schema (initial)

```json
{
  "id": "japanese",
  "name": "Japanese",
  "nativeName": "日本語",
  "writingSystems": ["hiragana", "katakana", "kanji"],
  "characterKeys": ["hiragana", "katakana", "kanji"]
}
```

Optional fields: `speech` (BCP 47 tag for text to speech, e.g. `ja-JP`),
`font` (`pIqaD` for Klingon), `direction` (`rtl`). The ids `hangul`, `cyrillic`
and `hindi` match the Character Learner's existing `?lang=` values.

## Shared files

- `registry.js` — every `meta.json` in one script, generated by
  `python3 languages/build_registry.py`. Tools fetch `meta.json` when served over
  http:// (the Desk's local server) and fall back to `registry.js` on `file://`,
  where browsers block `fetch()`. Run the script after editing any `meta.json`;
  `--check` exits 1 if `registry.js` is stale.
- `lsd-lang.js` — the loader the Vocabulary, Grammar and Language Learners use:
  reads `?lang=`, loads meta, language picker, text to speech, Klingon
  romanization → pIqaD.
- `learners.css` — the shared dark look of those three tools.
- `klingon/piqad.css` — the pIqaD qolqoS font (SIL OFL) as a data URL.

## Usage

- Character-learner and the grammar, vocabulary and language learners can be launched standalone or with `?lang=<id>`.
- When `?lang=` is present the tool scopes itself to that language only.
- Existing self-contained tools continue to work without this folder.
