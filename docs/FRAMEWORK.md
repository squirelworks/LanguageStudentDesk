# Shared content framework

Status: spec for the roadmap (#199, item #196). Each step below lands as its own
PR. The decision behind it (Nov 4, 2026): all language content lives in one
repo, [squirelworks/squirrel-lang-data](https://github.com/squirelworks/squirrel-lang-data),
which LanguageStudentDesk and squirrelator both pull in as a git submodule at
`data/`.

## Why

Language content lives in more than one place today. The Desk learners read
`languages/<id>/`, the SquirrelGo apps keep their own copies in `www/data/`
(Alphabets scripts and strokes, Kana, Bopomofo, Kanji, Klingon, Phrasebook
packs), and some learners hold data of their own (the Translation Learner's
meaning columns, the Programming Learner's courses). A fix in one copy doesn't
reach the others, and nothing notices when they drift.

The goal is one source for every kind of content that every app builds from,
with checks that stop drift and schema errors before a merge.

## Principles

1. **One source.** Every piece of content has one home in squirrel-lang-data.
   Everything an app ships is generated from it.
2. **Plain data.** The source is JSON for records and JSONL for big lists, never
   `window.X = …` scripts. Generators make what each app needs.
3. **Modules don't touch each other.** A module is one language, one shared
   character table or one programming course. Changing a module touches only
   its folder, plus indexes a tool rebuilds.
4. **Generated by a tool, never copied by hand.** A hand-edited copy in an app
   fails CI.
5. **Versioned schemas.** Every content file names the schema version it
   follows, and CI validates it.
6. **Works offline and from `file://`.** Generated files for the Desk and the
   apps stay plain scripts that assign a global, so the Desk runs from a folder
   and every app's `www/` runs on its own.
7. **Imports are tools.** Content from an outside source is made by a script
   under `tools/` and listed in `SOURCES.md` with its license.

## The data repo

```
squirrel-lang-data/
  languages/<id>/
    meta.json                 the language: names, scripts, speech, varieties
    grammar.json              grammar course, lessons tagged by level
    vocab.jsonl               one word per line, tagged by level and frequency
    reference.json            reference cards
    characters.jsonl          one character per line, for its scripts
    strokes/<script>.jsonl    one character's strokes per line
    varieties/<variety>/      a regional or historical variety: only what
                              differs from the parent
    REVIEW.md                 human review record (#198)
  cjk/
    characters.jsonl          hanzi, kanji and hanja table, tagged by tradition
    strokes/<standard>.jsonl  strokes by regional standard (TW, HK, CN, JP, KR)
  variants/                   links between character forms
  meaning/                    meaning matrix, columns per language, network
  programming/<id>/           course, keyword map, and its group
  features.json               every user-facing feature switch (#201)
  schemas/<type>.v<N>.json    JSON Schema per content type and version
  tools/                      validators, generators, importers, stroke checks,
                              the export tool
  SOURCES.md                  every source, its license and attribution
```

### File format

- **JSON** for records: `meta.json`, `grammar.json`, `reference.json`,
  `features.json`, a course. The top level has `"schema": "<type>@<N>"`.
- **JSONL** for big lists: vocabulary, characters, strokes, corpora. The first
  line is a header with `"schema"` (and `source`/`license` for imported data),
  and each later line is one entry. One entry per line keeps PR diffs readable
  and lets two PRs edit different entries without conflicting.
- A formatter in `tools/` fixes key order and layout, and CI fails on
  unformatted files, so diffs only show real changes.

### Content types

| Type | File | Entry |
|---|---|---|
| `meta` | `meta.json` | `id`, names, `scripts`, `speech`, `direction`, `font`, `varieties` |
| `variety` | `varieties/<v>/meta.json` | `id`, `parent`, `kind` (standard, regional, historical), `code` (ISO 639-3 or Glottolog), `period`, `scripts`, `romanization` |
| `characters` | `characters.jsonl` | `char`, `script`, `roman`, sound hint, examples, IPA |
| `cjk` | `cjk/characters.jsonl` | `char`, `uses` (hanzi, kanji, hanja), `radical`, `strokes`, readings per tradition |
| `strokes` | `strokes/<script>.jsonl` | `char`, `paths` (in a 100 × 100 box); the header names the source and license |
| `vocab` | `vocab.jsonl` | `id`, `word`, reading, meaning, `deck`, `level` (`{ "jlpt": "N5" }` and so on), `freq` (core, common, rare) |
| `grammar` | `grammar.json` | lessons with `level`; drills whose `answer` is one of `options` |
| `reference` | `reference.json` | today's card format, plus `level` and `sources` |
| `meaning` | `meaning/<id>.jsonl` | tokens `[text, romanization, meaning id]` |
| `course` | `programming/<id>/course.json` | today's course format, plus `group` (modern, older, joke) |
| `features` | `features.json` | `id`, `label`, `description`, `level` (simple, more, everything), `featured` |

A variety only overrides what differs from its parent; it never copies the
parent's data. A breaking schema change means a new version (`vocab@2`);
adding an optional field doesn't. CI accepts every version still in `schemas/`,
and an old version is dropped once no file uses it.

## How apps get content

LanguageStudentDesk adds the data repo as a submodule:

```
git submodule add https://github.com/squirelworks/squirrel-lang-data data
git submodule update --init      # after cloning
```

Generators in the data repo's `tools/` turn the plain data into what each
consumer ships:

- **Desk learners:** `registry.js`, `reference.js` and the per-language data
  scripts that `lsd-lang.js` loads today, written into `languages/`.
- **SquirrelGo apps:** each app's `www/data/` files, in the shape its code
  already reads (`SG_SCRIPTS`, `SG_STROKES`, `KANJI_STROKES` and so on). Each
  app lists what it takes in a small `content.json` next to `www/`, by module
  and kind, with filters (for example every alphabetic script), so a new
  language reaches the app with no edit to the app.
- **squirrelator:** Python modules or JSON, from the same submodule. When it runs
  inside LanguageStudentDesk, it reads LanguageStudentDesk's `data/` (passed with
  `SQUIRREL_LANG_DATA` or an argument).

Every generated file starts with a header that says it's generated, from which
data commit, and by which command. Apps keep a committed copy so their `www/`
still runs on its own. The build (`sync-shared.sh`, `pack-www.gradle`, the Desk
launcher) runs the generators' `--check` mode, so a copy that differs from the
pinned data can't ship.

Moving the pinned data commit forward is its own PR ("Bump squirrel-lang-data
to `<sha>`"), plus only the regenerated files and build changes it needs.

## Adding a module

1. In squirrel-lang-data, add the folder (`languages/<id>/meta.json`, or
   `programming/<id>/`) and its content files, each naming its schema. Imported
   content comes from a tool, with its source in `SOURCES.md`.
2. Merge it there. CI validates it.
3. In LanguageStudentDesk, bump the submodule and commit the regenerated files.

Nothing outside the module's folder is hand-edited. Pickers and menus list
modules alphabetically from the registry, with none pinned. New options become
feature switches in `features.json`, not main-menu entries.

## Checks in CI

In squirrel-lang-data, on every PR:

- **Schema:** every file validates against the version it names.
- **Format:** the formatter finds nothing to change.
- **Data tests (#198):** duplicate ids and characters, missing translations,
  missing level or frequency tags on vocabulary, broken links between modules,
  drill answers missing from their options, variety overrides with no parent.
- **Strokes (#188):** the final-frame and stroke-count checks.
- **Attribution:** every imported file's header names a source listed in
  `SOURCES.md`.

In LanguageStudentDesk:

- **Pinned commit exists** on the data repo's `main`.
- **Drift:** the generators' `--check` finds no app copy that differs from the
  pinned data.

## Moving content out of LanguageStudentDesk

One content type at a time, as a pair of PRs:

1. **Data repo PR:** adds the content (converted from LanguageStudentDesk at a
   named commit), its schema, its validator and its generator. It merges first.
2. **LanguageStudentDesk PR:** adds or bumps the submodule, switches the build to
   generate from `data/`, removes the old copy, and shows the generated output
   matches what was there (or explains every difference). It waits until the
   submodule points at the merged data PR.

Order:

1. The variety model in the meta schema, then language meta and the registry.
2. Vocabulary, grammar and references.
3. Characters and strokes, after the stroke checks from #188 are in place.
4. The meaning network.
5. Programming courses.

Content is never deleted from LanguageStudentDesk before the data repo has it on
`main`.

## Out of scope here

- Native apps (#197). A native app would read the same data repo through its own
  generator, so this spec doesn't block that decision.
- Audio files, which stay with their apps until the text content has moved.
- Changing any learner's UI.
